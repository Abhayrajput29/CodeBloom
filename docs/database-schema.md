# CodeBloom Database Schema Design

**Status:** Logical schema proposal, not yet a production migration. Supabase `auth.users` remains the identity authority. Enable RLS on all application tables. Use UUID primary keys and UTC `timestamptz` values (`created_at DEFAULT now()`; mutable rows also have `updated_at`).

## General conventions

- Name SQL columns `snake_case`; use `uuid` identifiers generated by `gen_random_uuid()` unless using a composite natural key.
- Keep `created_at` immutable. Update `updated_at` through a common trigger.
- Use `ON DELETE CASCADE` only for dependent records. Prefer `SET NULL` or `RESTRICT` where audit/history retention matters.
- Public visibility is explicit. Queries and RLS must preserve project/post visibility through joins.
- Use checks and unique constraints as the final duplicate-prevention mechanism, not only application checks.
- Index foreign keys used by reads, joins, ownership checks, and chronological pagination.
- Private rows must not be exposed by broad policies or public views.

## Identity

### `profiles`

- `id uuid PK REFERENCES auth.users(id) ON DELETE CASCADE` (required).
- `username text NOT NULL UNIQUE`; normalized lowercase, format/length check.
- `display_name text NOT NULL`; `bio text NULL`; `avatar_path text NULL`; `website_url text NULL`.
- `created_at timestamptz NOT NULL`; `updated_at timestamptz NOT NULL`.
- Index: unique normalized username (the unique constraint may provide it).
- Authorization: public profile fields readable; only matching authenticated user can edit their profile. Sensitive auth attributes stay in Auth, not copied here.

### `user_follows`

- `follower_id uuid NOT NULL FK profiles`; `followed_id uuid NOT NULL FK profiles`; `created_at timestamptz NOT NULL`.
- Composite PK `(follower_id, followed_id)`; check IDs differ.
- Index `(followed_id, created_at DESC)`.
- Authorization: user creates/deletes only a row whose `follower_id = auth.uid()`; reads may be public according to product privacy choice.

## Project discovery

### `projects`

- `id uuid PK`; `owner_id uuid NOT NULL FK profiles`.
- `name text NOT NULL`; `slug text NOT NULL`; `summary text NOT NULL`; `description text NULL`.
- `visibility text NOT NULL DEFAULT 'public' CHECK IN ('public','unlisted','private')`.
- `repository_url text NULL`; `github_owner text NULL`; `github_repo text NULL`; `github_node_id text NULL`.
- Cached fields: `github_description text NULL`, `github_stars integer NULL CHECK >= 0`, `github_forks integer NULL CHECK >= 0`, `github_language text NULL`, `github_default_branch text NULL`, `github_pushed_at timestamptz NULL`, `github_metadata_fetched_at timestamptz NULL`.
- `created_at`, `updated_at` required.
- Unique `(owner_id, slug)`; optional unique `(github_owner, github_repo)` when both non-null.
- Indexes `(visibility, created_at DESC, id)`, `(owner_id, created_at DESC, id)`.
- Authorization: public rows readable; private/unlisted access must follow explicit policies (unlisted means link-access only, not necessarily secret); only owner may update/delete. GitHub cache fields are server-updated or owner-submission-controlled, never trusted as authoritative.

### `project_tags`

- `project_id uuid NOT NULL FK projects ON DELETE CASCADE`; `tag text NOT NULL`; `created_at timestamptz NOT NULL`.
- PK `(project_id, tag)`; lowercase/length check.
- Index `(tag, project_id)`.
- Authorization: follows project visibility; owner manages tags. A normalized `tags` table can be added if tag aliases/moderation require it.

### `project_media`

- `id uuid PK`; `project_id uuid NOT NULL FK projects ON DELETE CASCADE`.
- `storage_path text NOT NULL UNIQUE`; `alt_text text NOT NULL`; `position integer NOT NULL DEFAULT 0 CHECK >= 0`; `created_at`.
- Index `(project_id, position, id)`.
- Authorization: read follows project visibility; project owner writes/deletes. Storage object policy must independently validate ownership/path.

### `project_updates`

- `id uuid PK`; `project_id uuid NOT NULL FK projects`; `author_id uuid NOT NULL FK profiles`.
- `title text NOT NULL`; `body text NOT NULL`; `created_at`, `updated_at`.
- Index `(project_id, created_at DESC, id)`.
- Authorization: public read only when parent project is public; writes by project owner or explicitly authorized project collaborator (collaborators are not in initial scope).

### `project_relationships`

- `id uuid PK`; `source_project_id uuid NOT NULL FK projects`; `target_project_id uuid NOT NULL FK projects`; `created_by uuid NOT NULL FK profiles`.
- `relationship_type text NOT NULL CHECK IN ('inspired_by','forked_from','alternative_to','related_to')`; `created_at`.
- Check source differs from target; unique `(source_project_id,target_project_id,relationship_type)`.
- Index `(target_project_id, relationship_type, source_project_id)`.
- Authorization: readable only if both projects are visible; create/remove by source owner or a carefully defined authorized user.

### `bookmarks`

- `user_id uuid NOT NULL FK profiles`; `project_id uuid NOT NULL FK projects`; `created_at`.
- Composite PK `(user_id, project_id)`.
- Index `(user_id, created_at DESC, project_id)`.
- Authorization: only owner can read/write their bookmarks; private project access still checked before bookmarking.

## Community interaction

### `posts`

- `id uuid PK`; `author_id uuid NOT NULL FK profiles`; `project_id uuid NULL FK projects`.
- `post_type text NOT NULL CHECK IN ('showcase','discussion','question','update')`.
- `title text NOT NULL`; `body text NOT NULL`; `visibility text NOT NULL DEFAULT 'public' CHECK IN ('public','unlisted')`.
- `created_at`, `updated_at`.
- Indexes `(created_at DESC, id)`, `(project_id, created_at DESC, id)`, `(author_id, created_at DESC, id)`.
- Authorization: publicly readable per visibility and parent-project visibility; only author edits/deletes.

### `comments`

- `id uuid PK`; `post_id uuid NOT NULL FK posts ON DELETE CASCADE`; `author_id uuid NOT NULL FK profiles`.
- `parent_comment_id uuid NULL`; `body text NOT NULL`; `created_at`, `updated_at`; `deleted_at timestamptz NULL` for soft deletion.
- Add `UNIQUE (id, post_id)`; composite self-FK `(parent_comment_id, post_id) REFERENCES comments(id, post_id)` enforces same-post parent. Check parent is not self.
- Index `(post_id, parent_comment_id, created_at, id)`, `(author_id, created_at DESC, id)`.
- Authorization: reads follow post visibility; only author edits/deletes own comment. Parent and child visibility must be handled consistently; soft delete preserves reply structure.

### `votes` (recommended referentially safe form)

- `id uuid PK`; `user_id uuid NOT NULL FK profiles`.
- Nullable `project_id uuid FK projects`, `post_id uuid FK posts`, `comment_id uuid FK comments`.
- `value smallint NOT NULL CHECK value IN (-1,1)`; `created_at`, `updated_at`.
- CHECK exactly one target FK is non-null.
- Partial unique indexes `(user_id, project_id) WHERE project_id IS NOT NULL`, `(user_id, post_id) WHERE post_id IS NOT NULL`, `(user_id, comment_id) WHERE comment_id IS NOT NULL`.
- Target lookup indexes on each non-null target FK.
- Authorization: authenticated user owns `user_id`; target must exist and be visible/votable. A server mutation or constrained database function changes/removes own vote. `id` is useful for audit/debug but one vote per user and target is enforced by target-specific unique indexes.

### `notifications`

- `id uuid PK`; `recipient_id uuid NOT NULL FK profiles`; `actor_id uuid NULL FK profiles`.
- `notification_type text NOT NULL`; `entity_type text NULL`; `entity_id uuid NULL`; `read_at timestamptz NULL`; `created_at`.
- Index `(recipient_id, created_at DESC, id)`; partial unread index `(recipient_id, created_at DESC) WHERE read_at IS NULL`.
- Authorization: recipient reads/marks own notifications; creation is trusted server/database workflow. Do not expose private entity details through generic notification payloads.

## Private communication

### `chat_requests`

- `id uuid PK`; `sender_id uuid NOT NULL FK profiles`; `recipient_id uuid NOT NULL FK profiles`.
- `intro_message text NOT NULL`; `status text NOT NULL DEFAULT 'pending' CHECK IN ('pending','accepted','declined','cancelled')`.
- `created_at`, `updated_at`; `responded_at timestamptz NULL`; check sender differs from recipient.
- Partial unique index on canonical pair `(least(sender_id,recipient_id), greatest(sender_id,recipient_id)) WHERE status='pending'` to prevent concurrent reverse-direction pending requests. PostgreSQL immutable expression/index behavior must be validated; an alternative generated pair columns or trigger is acceptable.
- Index `(recipient_id,status,created_at DESC)`, `(sender_id,status,created_at DESC)`.
- Authorization: only sender/recipient reads; only sender creates/cancels own pending request; only recipient accepts/declines. A user block forbids request creation and transition to accepted.

### `conversations`

- `id uuid PK`; `chat_request_id uuid NOT NULL UNIQUE FK chat_requests`; `status text NOT NULL DEFAULT 'open' CHECK IN ('open','closed')`; `created_at`, `updated_at`, `closed_at timestamptz NULL`.
- Index `(status, updated_at DESC)` only if operationally useful.
- Authorization: only participants can read; create only in atomic accepted-request workflow. A closed conversation disallows further ordinary message insertion.

### `conversation_participants`

- `conversation_id uuid NOT NULL FK conversations ON DELETE CASCADE`; `user_id uuid NOT NULL FK profiles`; `joined_at timestamptz NOT NULL`; `last_read_at timestamptz NULL`.
- PK `(conversation_id,user_id)`; initial application invariant requires exactly the accepted request's two distinct users.
- Index `(user_id, joined_at DESC)`.
- Authorization: user may read/update their own participant receipt; rows created only by trusted accept-request workflow.

### `messages`

- `id uuid PK`; `conversation_id uuid NOT NULL FK conversations ON DELETE CASCADE`; `sender_id uuid NOT NULL FK profiles`.
- `body text NOT NULL`; `created_at timestamptz NOT NULL`; `edited_at timestamptz NULL`; `deleted_at timestamptz NULL`; nonblank/body-size checks.
- Index `(conversation_id, created_at, id)`.
- Authorization: participant-only reads; sender must be a participant; parent conversation must be open; neither direction may be blocked. RLS is supplemented by a transaction-safe server/RPC check.

### `user_blocks`

- `blocker_id uuid NOT NULL FK profiles`; `blocked_id uuid NOT NULL FK profiles`; `created_at timestamptz NOT NULL`.
- PK `(blocker_id,blocked_id)`; check distinct IDs.
- Index `(blocked_id,blocker_id)`.
- Authorization: only blocker reads/manages their own block rows. Block existence is checked by trusted policy helper/functions without granting public access to the block graph.

## Safety and moderation

### `reports`

- `id uuid PK`; `reporter_id uuid NOT NULL FK profiles`; `target_type text NOT NULL`; `target_id uuid NOT NULL`.
- `reason text NOT NULL`; `details text NULL`; `status text NOT NULL DEFAULT 'open' CHECK IN ('open','reviewing','resolved','dismissed')`; optional `assignee_id uuid FK profiles`; `created_at`, `updated_at`.
- Index `(status,created_at)`, `(reporter_id,created_at DESC)`.
- Authorization: reporter submits and reads own reports; moderator role reads/updates queue. Prefer typed nullable target FKs for strict integrity; if polymorphic target is used, validate existence in a trusted function/trigger.

### `moderation_actions`

- `id uuid PK`; `moderator_id uuid NOT NULL FK profiles`; `target_type text NOT NULL`; `target_id uuid NOT NULL`.
- `action_type text NOT NULL`; `reason text NOT NULL`; `metadata jsonb NOT NULL DEFAULT '{}'`; `created_at`; `expires_at timestamptz NULL`.
- Index `(target_type,target_id,created_at DESC)`, `(moderator_id,created_at DESC)`.
- Authorization: no public access; actions written/read only by authorized moderators or a trusted server function. Preserve audit records; avoid cascading deletion.

## RLS policy matrix (summary)

| Data | Anonymous | Authenticated owner/participant | Other authenticated users | Moderator/service |
|---|---|---|---|---|
| Public profiles/projects/posts/comments | Read public rows | Write own rows | Read public rows | Moderation actions as defined |
| Private/unlisted project data | Deny except explicit public link policy for unlisted | Owner access | Deny unless explicitly shared | Narrow, audited support access only |
| Votes | Read aggregate/public rows only if policy permits | Insert/update/delete own vote | Cannot mutate another user's vote | Trusted moderation only |
| Bookmarks, follows | No bookmark access | Own rows | No bookmark access | No routine access |
| Chat requests/messages/participants | Deny | Request parties / conversation members only | Deny | No routine access; narrowly authorized investigations |
| User blocks | Deny | Blocker only | Deny | No routine access |
| Reports/moderation actions | Deny | Reporter sees own report | Deny | Moderator-only queue/actions |

RLS policies need SQL tests for positive and negative cases. Policies should avoid recursive policy dependencies; use carefully reviewed `SECURITY DEFINER` helpers with fixed `search_path` only when necessary. Do not grant execution of privileged functions to `public` by default.
